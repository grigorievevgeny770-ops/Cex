# Подключение заявок производства

Основа экранов и DTO взята из PR №1 и проверяется против нового API репозитория sklad. Backend не копируется в Android. Полный серверный контракт: PRODUCTION_REQUESTS.md в серверном PR.

Новый сервер объявляет requests, sheet-requests и stock-summary в OpenAPI. Android показывает заявки целиком: «Взять в работу» → «Изготовлено» → «Передано на склад». Отмена изготовления и передачи требует подтверждения. Создание и отмена самой заявки остаются в веб-приложении менеджера. Каталог фактического расхода читается из request-catalog?sheets=true; признак is_sheet общего каталога сам по себе не разрешает материал.

Сохранены cookie-сессия с Android Keystore, точные BigDecimal, Room-журнал исходных байтов и client_token, отсутствие автоматического replay неизвестного исхода. Миграция Room 1→2 добавляет scope и разделяет активные слоты старых заданий, заявок, создания запросов листа и приёмки. Тела старых команд не меняются. Подтверждённый запрос листа не мешает впоследствии заказать такую же новую доставку. Неизвестный запрос блокирует новую отправку и доступен для явного повтора на экране листа.

Сборка: JDK 25 для Gradle, JDK 17 для toolchain, SDK 36. На Windows аргумент `'-Pandroid.injected.testOnly=false'` нужно заключать в кавычки. Проверки: `gradlew.bat test lint assembleDebug '-Pandroid.injected.testOnly=false' --no-configuration-cache`. Дополнительно `python scripts/check-architecture.py`. Перед передачей APK проверить aapt/apksigner согласно scripts/build-debug-apk.sh. Эмулятор пока не использован; instrumentation/UI-проверки на Android нельзя считать пройденными.

Перед TEST проверить обновление Room со старым неизвестным запросом, потерю ответа с повтором неизменных байтов, два устройства, подтверждения отмен и один полный цикл приёмка листа → выпуск → передача → обе отмены. Серверная норма пока означает проверенный расход точно такой же партии; другие количества требуют нового фактического расхода.
