## 3. Согласованный производственный процесс

Менеджер создаёт заказ/заявку в веб-sklad2, работник использует общий планшет/телефон/ПК без назначения заявки человеку или устройству. Несколько каталожных позиций с размерами и количеством, желаемая дата и комментарий. Каталожная ветка МП подтверждена пользователем: «Металл Профиль → Стандартные элементы отделки», категория 1538, все потомки. Произвольные товары не добавляются.

Статусы: Новая → В работе → Изготовлено → Передано на склад; отдельно Отменена. Выпуск целиком, частичного выпуска нет. До передачи изделия остаются в цеху. Передача закрывает производственную заявку без дополнительного подтверждения склада. Отмена изготовления/передачи - с подтверждением и обратными движениями, история сохраняется. Если клиенту продукция уже выдана, сначала требуется отменить выдачу.

Лист принимается отдельным потоком: запрос → подтверждение/отгрузка менеджером → приёмка работником. Выпуск списывает плоский лист. Есть прежний путь нормы/фактического расхода и новый серверный точный расчёт по чертежу. Не выдумывать нормы, гибочные вычеты или каталожные конверсии.

Менеджер может создать клиентский заказ со связанной производственной заявкой одной транзакцией либо прикрепить производство к существующему заказу без второго заказа. Передача резервирует готовую продукцию под заказ; выдача/отмена выдачи используют существующий native ledger. После отмены ошибочной заявки можно создать исправленную для тех же позиций, не дублируя клиентский заказ. Реквизиты/фирма/скидка/флаги печати меняются до выдачи, с версией и idempotency.

Фактический scope нового customer-catalog сейчас включает весь «Цех» и МП → «Стандартные элементы отделки»; изначально в задании было «Цех → Стандартные». Это отражено в прежней документации и интерфейсе. Перед PROD сверить, что расширение scope действительно нужно; не расширять молча дальше.

## 4. Точные правила чертежа и расхода

- Полки задаются целыми миллиметрами; длина изделия отдельно. Углы строго между 0 и 180°, до 3 знаков. Косой профиль имеет отдельные размеры полок начала/конца, общие углы и направления сгибов.
- Подгиб и фальц добавляют по 10 мм на обработанный край один раз. Введённая полка 100 мм + подгиб даёт 110 мм заготовки; введённые 100 остаются размером полки.
- По позднему зафиксированному согласованию противоположные размеры 150→130 и 80→100 дают max(150+80,130+100)=230 мм до обработки краёв. Именно это реализовано и протестировано; не суммировать максимумы отдельных полок до 250. Исторические вопросы/ответы могут содержать прежнюю неоднозначность.
- Площадь/конверсии/материал рассчитывает сервер. Проверяются совпадение цвета/толщины изделия и листа, однозначная конверсия в штуки, остаток. Снимок расчёта сохраняется. Материал с неизвестными данными не подменяется автоматически.
- Перед выпуском Android/веб читает area-preview с request_version, preview_hash, площадями и материалами. Manufacture-area повторяет расчёт под writer lock, проверяет hash и остатки. Старый APK без hash сохраняет прежний fingerprint/replay.
- Мышь задаёт эскиз, не миллиметры. После «Рисовать» сразу пустая сетка; пунктир от последней точки следует за мышью без сетевых запросов. Клик закрепляет вершину. Отмена возвращает прежний профиль. Touch-прокрутку не перехватывали; реальный стилус не проверен.
- После завершения эскиза сохраняются силуэт, пропорции и ориентация; поля длин и углов пустые, нет подстановок 100/90. Пока не введены реальные числа, нет расчёта/сохранения готового чертежа. Затем точный профиль строится по числам.
- Полка/строка таблицы выбираются вместе. Нажатие на размер или угол на SVG открывает ввод числа; есть undo и удаление полки с подтверждением. Размерные подписи размещаются без перекрытия контура, сложные SVG могут расти по высоте.
- `rotation_deg` - угол первой полки от направления вправо, положительный против часовой стрелки, −180..180, до 3 знаков; 0 исключается из сериализации для сохранения старых fingerprints.
- `coating_side` left/right/null - единая окрашенная поверхность листа по ходу от края 1 к краю 2. Кнопки указать/перевернуть/не указывать, undo. Синяя полоса условная, не RGB-соответствие RAL. Для обоих концов косого изделия сторона одинакова. Новое рисование сбрасывает выбор. Null исключается из сериализации, старым чертежам сторона не назначается. На расход не влияет.
- Работник/Android видит пассивный серверный SVG, редактирование только в веб-менеджере. Совместимость неизвестных JSON-полей Android проверена по `ignoreUnknownKeys=true`.

## 6. Печатные формы

Чек/счёт/ТОРГ-12 используют существующий рендерер склада. Их предпросмотр не требует чертежей/листа/даты и не создаёт заказ.

Отдельное «Задание в цех» реализовано по одобренному компактному макету: А4 горизонтально, таблица с номерами, названием/цветом/толщиной, векторными профилями/размерами/углами, длиной/количеством, краями и заготовкой. Шапка и номер страницы повторяются. Строки цельные, высота адаптивная, основной текст/размеры 10 pt, подвал 9 pt. Сторона окраски обозначена пунктиром для чёрно-белой печати; косое изделие - начало/конец. Нет цен/скидок. Геометрия из структурированного чертежа, без сетки/редакторских выделений. Нет чертежа - явно написано, профиль не выдумывается.

Доступ: кнопка «Задание в цех · PDF» у сохранённой заявки менеджера/работника; ссылка после создания заказа; также первый пункт «Просмотр → Задание в цех» на форме создания ДО сохранения. Последний путь печатает текущие локальные чертежи, явно «ПРЕДПРОСМОТР / Не сохранено», без выдуманных номера/версии заявки. Не требует даты/клиента/выбора материала. Создание заявки остаётся строгим.

API:
- GET `/api/workshop/v2/requests/{request_id}/production.pdf?expected_version=N` - snapshot сохранённой заявки; без параметра актуальная версия, при устаревшей версии 409. Доступ чтения склада, без финансовых прав. No-store/inline.
- POST `/api/workshop/v2/customer-orders/pdf/production` - WorkshopCustomerPreviewIn с optional drawing/due_at; менеджер+каталог, для existing_order_id проверяется content_hash.
- Для старых финансовых kind payload остаётся прежним; drawing передаётся формой только для production.

Ограничения: 30 тестовых разных профилей заняли 6 листов, не гарантируется ровно 8 строк на странице. Слишком сложная строка или чрезмерный комментарий шапки дают понятную 422, а не обрезку/микрошрифт. Полноформатное приложение для таких крайних случаев ещё не реализовано. Нужна физическая печать 100%.
