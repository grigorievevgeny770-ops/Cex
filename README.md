# Цех — Android

Kotlin / Jetpack Compose приложение работника склада. Разработка ведётся по
MOBILE_TODO.md; текущая версия может содержать ещё незавершённые сценарии.
Производство v2 является проектируемым серверным контрактом; v1 manual
manufacture не используется вместо него.

## Инструменты

Android SDK Platform 36, Build Tools (устанавливаются Android Studio), JDK 25
для Gradle daemon (Android Studio bundled JBR), JDK 17 для JVM toolchain.
Gradle wrapper 9.6.0, AGP 9.5.0. minSdk 26, compile/target SDK 36.
Kotlin 2.3.21, KSP 2.3.9, Hilt 2.60.1, Compose BOM 2026.03.00.
Проверенные версии зафиксированы в `gradle/libs.versions.toml`.
`local.properties` с sdk.dir является локальным и не входит в Git.

## Проверки и сборка

Из корня проекта:

```sh
./scripts/verify.sh
# эквивалентно:
python3 scripts/check-architecture.py
./gradlew test lint assembleDebug
# при работающем эмуляторе:
CONNECTED_TESTS=1 ./scripts/verify.sh
# только UI:
./gradlew connectedDebugAndroidTest
```

Debug APK: `app/build/outputs/apk/debug/app-debug.apk`.
Установка: `adb install -r app/build/outputs/apk/debug/app-debug.apk`.

## Окружения

Debug по умолчанию подключается к локальному backend через Android Emulator:
`http://10.0.2.2:8000/`. Сохранённый выбор окружения имеет приоритет.
Адрес выбирается в приложении; логины и пароли не включены в исходники.
Release URL задаётся `-PreleaseBaseUrl=https://your-test-host/`; без настройки
используется намеренно нерабочий `https://example.invalid/`. Release требует HTTPS.
Для Android Emulator локальный backend: `http://10.0.2.2:8000/`.
Для телефона по USB: `adb reverse tcp:8000 tcp:8000`, затем
`http://127.0.0.1:8000/`. Не нужно открывать backend в LAN.
Debug допускает HTTP только localhost/127.0.0.1/10.0.2.2.
Release допускает HTTPS с системной проверкой сертификата.
Удалённый сервер может не поддерживать workshop API: см. API_CONTRACT.md.

## Границы

`app` связывает навигацию, DI и реализации; `domain` — чистый Kotlin/JVM;
`data` — HTTP/Room/secure storage; `core:ui` — общие компоненты;
`feature:auth`, `feature:tasks`, `feature:stock` — MVI/UI.
Features зависят только от domain/core:ui, domain не зависит от Android.
Проверка `scripts/check-architecture.py` контролирует зависимости.

Официальные справочники: [AGP](https://developer.android.com/build/releases/agp-9-5-0-release-notes),

## Сессия и безопасный повтор

Cookie сохраняются в AES-GCM файле в `noBackupFilesDir`, ключ находится в
Android Keystore. Пароль не сохраняется. При logout/смене сервера старые
ответы не могут восстановить сессию. Сохранённая сессия проверяется через
`auth/me`, ID пользователя берётся только из его ответа.

Room-журнал `pending-commands.db` содержит точные UTF-8 тела подтверждённых
пользователем команд до первого HTTP-запроса. Он изолирован по каноническому
серверу + числовому ID работника и сохраняется после logout/401.
После timeout/500/остановки процесса запрос повторяется только явно, с тем
же token и неизменённым телом. Автоматического фонового replay нет.
Подтверждение сервера и полный снимок task сохраняются атомарно до
освобождения слота задания. Неопределённый исход с последующим отказом прав
требует сверки; такая команда не выдаётся за обычный черновик.

Реальные Room-транзакции, конкуренция двух dispatcher и reopen дисковой БД
проверяются Robolectric (`:data:testDebugUnitTest`). HTTP contract tests
используют только MockWebServer, без записей в пользовательский backend.

## Задания

Склад разрешается по `code=workshop` из разрешённого массива (включая
неактивные для явной диагностики). Основной склад и первый элемент массива
не подменяют цех. Список запрашивает серверные фильтры и страницы по 50.
Обновление каждые 30 секунд действует только при RESUMED экране списка;
ручное обновление — жестом вниз. История и факты загружаются отдельными
страницами, а не ограничиваются вложенными последними 50 записями карточки.

Взятие в работу требует отдельного подтверждения и проходит через durable
CommandDispatcher. Неизвестные типы/статусы и legacy производство не
получают кнопок изменения. Журнал запросов доступен из раздела заданий;
после неопределённого исхода нужно повторять сохранённую команду.

## Приёмка и отправка

Обе формы вводят факт текущего шага, показывают отдельное подтверждение и
отправляют запрос через общий устойчивый журнал. Ввод поддерживает запятую
и до четырёх десятичных знаков без округления. Для frozen листовых строк
вводится только число листов; геометрия из текущего каталога не подставляется.

Приёмка позволяет продолжить ожидание либо завершить её, включая нулевой
финальный факт с причиной недостачи. Завершённая недостача остаётся на
разбор менеджеру. Отправка принимает только положительный физический факт:
товар уходит из цеха в путь, основной склад зачислит его после своей приёмки.
В payload отправки нет полей final/reason/expected_transfer_version.
После подтверждения карточка перечитывается с сервера; возврат к списку и
карточке обновляет серверные данные. Неопределённый исход блокирует новую
форму до безопасного восстановления сохранённого запроса.

Проверки форм используют synthetic fixtures и MockWebServer; живые складские
движения на пользовательской базе не выполнялись.
